# 발표용 PPT — KSA 모노톤

정체성은 한 줄로: **순백 A4 가로 위에 5개 존이 전 장표에서 흔들리지 않고, 색은 하나도 쓰지 않으며, 한 장에 메시지 하나와 도식 하나를 담는다.**

값(색·좌표·규칙)의 최종 권한은 **`references/design-system.md`**, 컴포넌트 사용법은 **`references/components.md`** 에 있다. 파일 조작 메커니즘은 **pptx 스킬**을 따른다.

## 0. 시작 전 확인

| 확인 | 조치 |
|---|---|
| **판형** | A4 가로(10.8333"×7.5")만. 16:9·4:3 요청은 거절하고 A4 가로로 제안 |
| **서체** | 맑은 고딕만. 대체 폰트 제안도 하지 않는다 |
| **색** | **무채색만.** 유채색을 넣지 않는다 |
| **로고** | `assets/ksa_logo.jpg`가 동봉돼 있고 자동으로 들어간다. 어두운 배경 장표에 로고가 필요하면 흰 반전본을 사용자에게 받는다 |
| **데이터** | 근거 없는 수치를 지어내지 않는다. 모든 데이터 요소에 출처 줄을 붙인다 |
| **보고서와의 구분** | 읽는 문서(표·각주 중심, 작은 글씨)라면 REPORT_PPT를 쓴다 |

## 1. 이 스킬의 밀도

발표용은 **크게 적게**다. 한 장에 KPI 4개 또는 도식 하나, 표는 5행 안팎.

| 헤드라인 | 부제 | 본문 | KPI 숫자 | 표 행 | 최소 글자 |
|---|---|---|---|---|---|
| 24pt | 13pt | 11.5pt | 34pt | 0.44" | **9.5pt** |

내용이 넘치면 글자를 줄이지 말고 **장표를 나눈다.** 헤드라인은 24pt 한 줄(한글 28자 안팎)이 한계다.

## 2. 만드는 법

```bash
SK=~/.claude/skills/PRESENT_PPT
mkdir build && cp $SK/assets/{ksa_mono.js,example_deck.js,ksa_logo.jpg} build/ && cd build
node example_deck.js deck.pptx                      # example_deck.js를 복사해 내용만 교체
python3 $SK/scripts/postprocess.py deck.pptx        # 필수 — 아래 설명
python3 $SK/scripts/check_layout.py deck.pptx --mode present --special 1,12
```

**`postprocess.py`는 선택이 아니다.** pptxgenjs 4.x가 차트에 *선언하지도 않은 축 참조*를 써 넣어, 그대로 두면 PowerPoint가 **"내용에 문제가 있습니다 / 복구하시겠습니까"** 대화상자를 띄운다. LibreOffice는 조용히 무시하므로 렌더 QA로는 드러나지 않는다. 점검기가 이를 검사하므로 빠뜨리면 FAIL로 막힌다.

`pptxgenjs`는 pptx 스킬 환경에 이미 설치돼 있다(`npm install` 먼저 하지 말 것).

작성 순서: ①장표별 헤드라인·부제를 텍스트로 먼저 설계 → ②장표별 도식 배정 → ③조립 → ④후처리·점검 → ⑤렌더 육안 QA.

## 3. 표준 골격 (12장 예시)

표지 → 목차 → 핵심 요약(KPI+3열) → 워터폴 → 드라이버 트리 → 체브론+게이트표 → 2×2 매트릭스 → 조직도 → 간트 → 3단 계층 → 성과지표 → 클로징(먹지).

`assets/example_deck.js`가 이 12장을 그대로 만든다. 복사해 내용만 갈아끼운다.

## 4. 도식 선택

| 상황 | 도식 |
|---|---|
| 핵심 지표 3–4개 | `kpiRow` (하나만 `dark:true`로 반전) |
| 증감 누적 설명 | `waterfall` |
| 요인 분해 | `tree` |
| 단계·절차 | `chevrons` |
| 우선순위 판단 | `matrix` |
| 일정 | `gantt` |
| 계층·체계 | `layers` |
| 조직·역할 | 조직도 도형 + `tableNative` |

## 5. 표

**데이터 표는 `tableNative`(PowerPoint 네이티브)를 기본으로 쓴다.** 머리글은 가운데 정렬·먹 배경이고, 셀 윤곽선은 그리지 않는다. 도식과 x좌표를 맞춰야 하는 표만 `table`(도형)로 남긴다.

네이티브 표는 글이 길면 행이 자란다. 헬퍼가 줄 수를 미리 추정해 본문 벽(6.85")을 넘으면 생성을 중단한다.

## 6. QA

```bash
python3 $SK/scripts/check_layout.py deck.pptx --mode present --special <표지·디바이더 번호>
python3 /mnt/skills/public/pptx/scripts/office/validate.py deck.pptx
soffice --headless --convert-to pdf deck.pptx && pdftoppm -png -r 78 deck.pdf p   # 전 장표 육안
```

점검기가 잡는 것 — A4 판형, 맑은 고딕 외 폰트(표·차트 내부까지), 9.5pt 미만, 슬라이드 밖 이탈, 본문 벽 침범(**네이티브 표는 `<a:tr h>` 합산으로 실제 높이 계산**), 5존 앵커 이탈, 하단 30% 공백, **의도하지 않은 검은 윤곽선**, 흐린 글자색, 유채색, 로고 위치·비율·로고 뒤 도형, 이모지, 차트 구조 결함.

**렌더 QA는 반드시 한다.** 좌표 점검만으로는 글자 넘침·요소 겹침을 못 잡는다. QA 머신에 맑은 고딕이 없으면 대체 폰트로 그려져 글줄 폭 판정이 부정확하므로, 폭이 애매하면 실물 PowerPoint 기준으로 판단하되 서체는 바꾸지 않는다.

## 7. 자주 하는 실수

- `line: { width: 0 }` — pptxgenjs가 무시하고 1pt `#333333` 선을 그린다. `line: { type: 'none' }`을 쓴다.
- 밑줄을 임의 길이로 — `textW()`로 글자 폭에 맞춘다.
- 구분선을 글자에 붙임 — 축 라벨 → 0.09" → 선 → 0.06" → 캡션 순으로 쌓는다.
- 흰 배경에 `#C7C7C7` 글자 — 최소 `#6B6B6B`.
- 표 열 폭 합계가 우측 여백 초과 — 헬퍼가 예외를 던진다.

## 8. 파일 규칙

- 산출 파일명: `<발표명>_v<n>.pptx`
- 동봉 자산(로고·모듈)은 수정하지 않는다 — 사본으로 작업
- 차트·표 텍스트는 라이브 텍스트로 유지한다
