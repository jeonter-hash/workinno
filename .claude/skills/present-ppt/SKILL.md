# 발표용 PPT — KSA 모노톤

정체성은 한 줄로: **순백 A4 가로 위에 5개 존이 전 장표에서 흔들리지 않고, 색은 하나도 쓰지 않으며, 헤드를 타이틀과 메시지로 나누고 한 장에 메시지 하나와 도식·차트 하나를 담는다.**

값(색·좌표·규칙)의 최종 권한은 **`references/design-system.md`**, 컴포넌트 사용법은 **`references/components.md`**, 표현을 고르는 기준은 **`references/diagrams.md`**, 헤드 문법은 **`references/headline.md`** 에 있다. 파일 조작 메커니즘은 **pptx 스킬**을, **논리 구조와 문안 언어는 `REPORT_CONTRACT`(`/report-contract`) 스킬**을 따른다.

## 0. 시작 전 확인

| 확인 | 조치 |
|---|---|
| **판형** | A4 가로(10.8333"×7.5")만. 16:9·4:3 요청은 거절하고 A4 가로로 제안 |
| **서체** | 맑은 고딕만. 대체 폰트 제안도 하지 않는다 |
| **색** | 무채색 뼈대 + KSA 강조 2색(`palette:'accent'`가 기본). 구조색 네이비 `#1F3864`, 강조색 레드 `#C4303C`는 **장표당 한 곳만** |
| **데이터** | 근거 없는 수치를 지어내지 않는다. 데이터 도식에는 단위·출처를 한 줄로 붙인다 |
| **보고서와의 구분** | 읽는 문서(표·각주 중심, 작은 글씨)라면 REPORT_PPT를 쓴다 |
| **논리·문안** | 구조 계약·문안 언어·미결정 처리·자기검증 게이트는 **REPORT_CONTRACT**(`/report-contract`) 스킬을 먼저 읽고 그 계약 아래에서 조판한다 |

## 1. 이 스킬의 밀도

발표용은 **크게 적게**다. 한 장에 KPI 4개 또는 도식 하나, 표는 5행 안팎.

| 헤드 타이틀 | 헤드 메시지 | 본문 | KPI 숫자 | 표 행 | 최소 글자 |
|---|---|---|---|---|---|
| 24pt | 13pt | 11.5pt | 34pt | 0.44~0.62" | **9.5pt** |

본문은 **2.11"–6.85"** (4.74")다. 좌표는 `deck.bt`로 읽고, **도형·표는 하단 기준선 6.85"까지 채운다.**

내용이 넘치면 글자를 줄이지 말고 **장표를 나눈다.** 헤드라인은 24pt 한 줄(한글 28자 안팎)이 한계다.

### 헤드 존 좌표

렌더 실측으로 잡았다. **타이틀↔메시지 = 메시지↔본문 = 0.14"**로 같다.
좌표를 손대려면 `scripts/measure_head.py`로 다시 재고 나서 고친다.

| | 발표용 | 보고서용 |
|---|---|---|
| 타이틀 | 0.94" · 24pt | 0.94" · 20pt |
| 메시지 | 1.43" · 13pt · 상자 0.62"(2줄분 고정) | 1.37" · 12pt · 상자 0.58"(2줄분 고정) |
| 본문 | 2.11" – 6.85" | 2.00" – 6.85" |
| 메시지 한 줄 | 54자 | 59자 |

메시지가 한 줄이어도 **본문 시작선은 그대로다.** 장표를 넘겨도 표·도식이 어긋나지 않는다.

## 2. 만드는 법

```bash
SK=<이 스킬 폴더 경로>          # 로컬은 ~/.claude/skills/PRESENT_PPT, 코워크는 마운트된 위치
mkdir build && cp $SK/assets/{ksa_mono.js,example_deck.js,photo_placeholder.png} build/ && cd build
node example_deck.js deck.pptx                      # 예시 11장 — 복사해 내용만 교체
python3 $SK/scripts/postprocess.py deck.pptx        # 필수 — 아래 설명
python3 $SK/scripts/check_layout.py deck.pptx --mode present --special 1,12
```

**`postprocess.py`는 선택이 아니다.** pptxgenjs 4.x가 차트에 *선언하지도 않은 축 참조*를 써 넣어, 그대로 두면 PowerPoint가 **"내용에 문제가 있습니다 / 복구하시겠습니까"** 대화상자를 띄운다. LibreOffice는 조용히 무시하므로 렌더 QA로는 드러나지 않는다. 점검기가 이를 검사하므로 빠뜨리면 FAIL로 막힌다.

`pptxgenjs`는 pptx 스킬 환경에 이미 설치돼 있다(`npm install` 먼저 하지 말 것).

작성 순서: ①장표별 헤드 타이틀·메시지를 텍스트로 먼저 설계 → ②장표별 도식 배정 → ③조립 → ④후처리·점검 → ⑤렌더 육안 QA.

## 3. 표준 골격 (11장 예시)

표지 → 목차 → 핵심 요약(KPI+3열) → 워터폴 → 드라이버 트리 → 체브론+게이트표 → 2×2 매트릭스 → 조직도 → 간트 → 3단 계층 → 성과지표.

`assets/example_deck.js`가 이 11장을 그대로 만든다. 복사해 내용만 갈아끼운다.

**표지는 사진으로 만든다. 로고는 넣지 않는다.**

```js
B.cover(deck, { org:'○○공단', title:'AX 전환 실행계획\n(최종보고)',
  date:'2026.01', by:'한국표준협회',
  photos:['공연.jpg','전경.jpg','교실.jpg','축제.jpg','대표.jpg'] });   // 생략하면 자리표시
```

상단에 사진 4장을 사선으로 나눈 띠, 좌하단 먹 패널(제목·날짜·수행기관), 우하단 대형 사진 1장으로 짠다.
사진 5장은 **각각 독립된 그림 도형**이라 PowerPoint에서 [그림 바꾸기]로 갈아끼워도 사선이 그대로 유지된다.
`photos`를 주지 않으면 `assets/photo_placeholder.png` 자리표시가 들어가므로, **사진 없이 먼저 출고하고 나중에 끼워 넣어도 된다.**

사선은 `postprocess.py`가 띠 사진의 도형을 평행사변형으로 바꿔 만든다 — **표지를 쓰면 후처리를 반드시 돌린다.**
사진이 없거나 격자 도형 표지를 쓰고 싶으면 `B.coverPlain(deck, {...})`을 쓴다.

**사진은 고객사 제공본을 우선한다.** 웹에서 가져올 때는 공공누리 1유형 또는 CC0/CC-BY(출처 표기)만 쓰고,
출처가 불분명한 이미지는 제출용 문서에 넣지 않는다.

**목차**

```js
B.toc(deck, { items:[{n:'01',t:'현황 진단',p:3},{t:'업무시간 구조와 절감 여력',p:3}, …] });
```

슬라이드 번호는 마스터의 자동 번호 필드가 하단 가운데에 넣고, 우측 상단 문서 제목도 마스터가 그린다(`docTitle`). 출처는 푸터가 아니라 해당 도식 아래에 붙이되, **단위와 출처를 한 줄로 합친다**. 각주는 오독 위험이 있을 때만, **결론 밴드(`callout`)는 장(章)의 마지막 장표에만** 단다 — 잔글씨 3줄 이상이거나 결론 밴드가 본문 장표의 60%를 넘으면 점검기가 경고한다.

## 4. 도식 선택

| 말하려는 것 | 도식 | 호출 |
|---|---|---|
| 핵심 지표 3–4개 | KPI 스트립 | `kpiRow` |
| 단계·절차 | 체브론 | `chevrons` |
| 증감 누적 | 워터폴 | `waterfall` |
| 요인 분해 | 드라이버 트리 | `tree` |
| 우선순위 판단 | 2×2 매트릭스 | `matrix` |
| 일정 | 간트 | `gantt` |
| 3단 체계 | 층 | `layers` |
| **집합·공통분모** | **벤 다이어그램** | `venn` |
| **하나의 중심에 붙는 여러 요소** | **허브&스포크** | `hubSpoke` |
| **반복되는 주기** | **순환 고리** | `cycle` |
| **아래가 위를 받치는 구조** | **피라미드** | `pyramid` |
| **단계마다 올라가는 성장** | **계단** | `steps` |
| **대안 3개 이상의 정성 비교** | **하비볼 평가표** | `harvey` |
| **현상이 결과로 이어지는 논리** | **원인→결과** | `causeEffect` |
| 조직·역할 | 조직도 도형 + `tableNative` | — |

**표는 값을 정확히 읽혀야 할 때만 쓴다.** 관계·구조·흐름은 위 도식으로, 수치의 크기·추세·구성비는 차트로 보인다.

무엇을 말하려는지에서 표현을 고르는 자세한 기준은 **`references/diagrams.md`** 를 볼 것.

**도형 안에 글을 넣을 때는 `panel()`을 쓴다.** 제목은 **좌우 가운데 정렬**하고 얇은 밑줄을 둔 뒤, 본문 항목을 **박스 높이에 맞춰 줄간격을 벌려** 아래가 비지 않게 채운다. 글이 넘치면 필요한 높이를 알려주며 생성을 멈춘다.

```js
B.panel(s, { x:B.cx(0), y:2.46, w:B.cw(6), h:1.86, title:'추진 배경', items:[
  { t:'관련 법령 개정으로 신규 사무가 신설되어 차년도부터 시행', sub:'시행 시점은 관계 부처 고시에 따름' },
  '재정당국 개편으로 예산 협의 창구와 심의 일정이 함께 이동',
]});
```

### 차트 — 수치는 표보다 차트로

**막대·선·원·혼합 네 가지를 쓴다.** 무채색이므로 **계열을 명도로만 구분하며 5개까지**다. 넘으면 생성이 멈춘다.

| 말하려는 것 | 차트 | 호출 |
|---|---|---|
| 항목 간 크기 비교 (이름 짧음) | 세로막대 | `barChart` |
| 순위 (이름 길거나 6개 이상) | 가로막대 | `barChart({horizontal:true})` |
| 계획 대비 실적 | 2계열 막대 | `barChart({series:[…]})` |
| 구성의 누적 | 누적 막대 | `barChart({stacked:true})` |
| 시간에 따른 추세 | 선 | `lineChart` |
| 구성비 (조각 5개 이하) | 원·도넛 | `pieChart` / `pieChart({hole:55})` |
| 규모와 비율을 함께 | 혼합 (막대+선) | `comboChart({rightAxis:true})` |

```js
B.barChart(s, { x:M, y:BT, w:CW, h:2.0, cats:['문서','데이터','판정'], values:[1900,1700,1500] });
B.lineChart(s, { x:M, y:BT, w:CW, h:2.1, cats:['1월','2월','3월'],
  series:[{ name:'실적', values:[12,24,38] }, { name:'목표', values:[15,30,45] }] });
B.pieChart(s, { x:M, y:BT, w:4.8, h:2.1, labels:['자동화','표준화','이관'], values:[3600,2700,1800] });
B.comboChart(s, { x:M, y:BT, w:CW, h:1.6, rightAxis:true, unit:'시간', unit2:'%',
  cats:['1분기','2분기'], bars:[{name:'절감', values:[820,1540]}], lines:[{name:'달성률', values:[91,96]}] });
```

**서식은 헬퍼가 고정한다.** 격자선을 그리지 않고, 값은 데이터 레이블로 직접 붙이며, 축선은 헤어라인이다. 계열이 하나면 범례를 두지 않는다.

- **가로막대**는 PowerPoint가 첫 항목을 맨 아래에 놓는다. 헬퍼가 되돌려 순위가 위에서 아래로 읽힌다
- **원 차트**는 상자의 짧은 변에 갇힌다. 정사각형에 가까운 상자에 넣고, 가로로 긴 상자면 범례를 오른쪽에 둔다(기본값). 레이블은 조각 **바깥**에 붙는다 — 먹 조각 위에서는 글자가 묻힌다
- **차트를 만들면 `postprocess.py`를 반드시 돌린다.** pptxgenjs가 선언되지 않은 축을 참조하고 한글 폰트를 빠뜨려 PowerPoint가 복구 대화상자를 띄운다. 축 제목 등에 Arial 18pt를 박아 넣는 것도 후처리가 고친다

## 5. 표

**데이터 표는 `tableNative`(PowerPoint 네이티브)를 기본으로 쓴다.** 머리글은 가운데 정렬·먹 배경이고, 셀 윤곽선은 그리지 않는다. 도식과 x좌표를 맞춰야 하는 표만 `table`(도형)로 남긴다.

네이티브 표는 글이 길면 행이 자란다. 헬퍼가 줄 수를 미리 추정해 본문 벽(6.85")을 넘으면 생성을 중단한다.

## 6. 문안 — 헤드와 본문은 규칙이 다르다

### 헤드 — 타이틀 + 메시지

**`references/headline.md`가 최종 권한이다.** 헤드를 쓸 때는 반드시 그 파일을 읽는다.
실제 컨설팅 보고서 87건에서 뽑은 문형과 예문 36개가 유형별로 정리돼 있다.

```js
B.head(s, { title:'업무별 시간 구조 및 절감 여력',
            message:'상위 4개 업무가 전체 업무시간의 45%, 절감 여력의 65%를 차지하는 반면 '
                  + '잔여 8개 업무는 정형비율이 낮아 절감 여력이 제한적임' });
```

- **타이틀** — 주제를 가리키는 명사구. 30자·1줄. 대분류는 챕터에 있으므로 넣지 않는다
- **메시지** — 판단을 담은 한 문장. **명사형 개조식**(`~함`·`~임`·`~해야 함`·`~할 수 있음`·`~이 필요함`)으로 끝낸다. 두 줄까지
- **한자어 명사구를 그대로 쓴다.** 재정건전화·부족재원·매출구조 개선처럼 압축된 한자어가 정보 밀도를 만든다. 풀어쓰면 설명문이 되어 헤드 구실을 못 한다
- 종결어미 비중을 지킨다 — **사실 진술이 절반**, 당위형(`~해야 함`)은 10% 안쪽
- `(근거)` 괄호와 `[대상]` 라벨을 쓴다. 범례는 메시지 뒤에 붙이되 두 줄로 쪼개지면 표 아래로 내린다

헤드에서는 `~ 필요함`·`~ 시`·`니즈`·`제고`가 **표준 표현이다.** 걷어낼 것은 넷뿐이다.

| 걷어낼 것 | 이유 |
|---|---|
| `되어지` `보여지` | 이중 피동 |
| `것으로 판단됨` `것으로 사료됨` | 상투구. 판단을 그대로 쓴다 |
| `대폭` `획기적` `비약적` | 수치 없는 평가어. 숫자로 대체한다 |
| `~합니다` `~입니다` | 서술체. 헤드는 명사형으로 끝낸다 |

### 본문 — 짧게

- 불릿 15~25자, 명사 종결. 표 셀은 값과 짧은 명사구만. 도식 라벨 10자 이내
- 콜아웃·각주도 **명사형 개조식**으로 끝낸다 — `…재설계함`, `…적용한 값임`
- 표를 그대로 읽는 문장은 결론이 아니다. 수치가 말하지 않는 함의를 적는다


점검기가 잡는 것 — A4 판형, 맑은 고딕 외 폰트(표·차트 내부까지), 9.5pt 미만, 슬라이드 밖 이탈, 본문 벽 침범(**네이티브 표는 `<a:tr h>` 합산으로 실제 높이 계산**), 5존 앵커 이탈(모드별), 하단 30% 공백, **본문 빈 띠**(0.45" 초과 — 도형·표를 늘려 채우라는 신호), **요소 겹침**(글자가 도형에 30% 이상 가림, **네이티브 표가 콜아웃·밴드와 겹침**), **의도하지 않은 검은 윤곽선**, 흐린 글자색, 팔레트 밖 색, 이모지, 차트 구조 결함, **헤드 문법**(타이틀 길이·메시지 종결·줄 수), **표 편중**.

`--palette accent`를 주면 강조 2색을 허용하고, 그 밖의 유채색은 여전히 잡는다.

점검기가 새로 잡는 것 — **표 편중**(표가 본문 65%를 넘게 차지한 장표), **표와 도형의 겹침**(네이티브 표는 graphicFrame이라 글자 겹침 규칙에 안 걸린다), **각주 과다**(잔글씨 3줄 이상), **결론 밴드 남용**(본문 장표 60% 초과), **문안**(이중 피동·상투구·수치 없는 평가어 — 헤드 존은 검사에서 뺀다).

**스킬 자체를 고쳤다면** 저장소 루트에서 `python3 tools/audit_skills.py`를 돌린다. 문서가 코드와 어긋났는지(좌표·규칙 번호·export·수치 주장·폐기 문구·명령어) 본다.

**렌더 QA는 반드시 한다.** 좌표 점검만으로는 글자 넘침·요소 겹침을 못 잡는다. QA 머신에 맑은 고딕이 없으면 대체 폰트로 그려져 글줄 폭 판정이 부정확하므로, 폭이 애매하면 실물 PowerPoint 기준으로 판단하되 서체는 바꾸지 않는다.

## 8. 자주 하는 실수

- **하단이 비었는데 그냥 둠** — 점검기의 `빈 띠` 경고가 나오면 도형·표를 6.85"까지 늘린다.
- `line: { width: 0 }` — pptxgenjs가 무시하고 1pt `#333333` 선을 그린다. `line: { type: 'none' }`을 쓴다.
- 밑줄을 임의 길이로 — `textW()`로 글자 폭에 맞춘다.
- 구분선을 글자에 붙임 — 축 라벨 → 0.09" → 선 → 0.06" → 캡션 순으로 쌓는다.
- 흰 배경에 `#C7C7C7` 글자 — 최소 `#6B6B6B`.
- 표 열 폭 합계가 우측 여백 초과 — 헬퍼가 예외를 던진다.
- **카드 제목을 왼쪽에 붙이고 글을 위로 몰아 아래를 비움** — `panel()`을 쓰면 제목이 가운데로 가고 본문이 박스를 채운다.
- **모든 장표에 결론 밴드를 붙임** — 장(章)의 마지막 장표에만 단다.

## 부록. 대규모 덱 제작 함정 (152장 실측)

- `gantt()`의 반환값은 **객체가 아니라 숫자**다. `g.bottom`이 아니라 `g`를 쓴다.
- 표 셀에 `—`를 쓰면 흐린 글자색 경고 — **빈 문자열이나 실제 낱말**('없음'·'해당 없음'·'미측정')을 쓴다.
- 소수점은 `fmt:'0.0'`을 반드시 준다. 없으면 4.64가 5로, 92.6이 93으로 렌더된다.
- 본문에 **0.7" 이상 빈 띠**가 남으면 경고 — rowH를 키우거나 패널로 채운다.
- **10행 표는 rowH 0.32 이하**, 12행 간트는 rowH 0.30이어야 아래 패널이 들어간다.
- 표가 본문의 65%를 넘는 장이 절반을 넘으면 deck 경고 — 차트·체브론·패널을 섞는다.
- 헤드 타이틀 30자를 넘기면 빌드 실패 — 긴 이름은 짧은 표시명 필드를 따로 둔다.
- 배치를 나눠 만들 때 **장수가 바뀌면 이후 모든 배치의 `firstSlideNum`을 다시 계산**한다.
- `rm -f *.png`가 `photo_placeholder.png`를 지운다 — 표지 빌드가 깨진다.
- 문서 속성 Author·Last saved by를 최종 치환하고 도구명을 남기지 않는다.
