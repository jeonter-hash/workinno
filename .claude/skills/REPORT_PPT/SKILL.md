# 보고서용 PPT — KSA 모노톤

정체성은 한 줄로: **순백 A4 가로 위에 5개 존이 전 장표에서 흔들리지 않고, 색은 하나도 쓰지 않으며, 한 장에 근거까지 담는다.**

값(색·좌표·규칙)의 최종 권한은 **`references/design-system.md`**, 컴포넌트 사용법은 **`references/components.md`** 에 있다. 파일 조작 메커니즘은 **pptx 스킬**을 따른다.

## 0. 시작 전 확인

| 확인 | 조치 |
|---|---|
| **판형** | A4 가로(10.8333"×7.5")만. 16:9·4:3 요청은 거절하고 A4 가로로 제안 |
| **서체** | 맑은 고딕만. 대체 폰트 제안도 하지 않는다 |
| **색** | **무채색만.** 유채색을 넣지 않는다 |
| **로고** | `assets/ksa_logo.jpg`가 동봉돼 있고 자동으로 들어간다 |
| **데이터** | 근거 없는 수치를 지어내지 않는다. 표에는 출처·산식·각주를 붙인다 |
| **발표덱과의 구분** | 화면에 띄우고 말로 설명하는 자료라면 PRESENT_PPT를 쓴다 |

## 1. 이 스킬의 밀도

보고서용은 **작게 많이**다. 한 장에 표 1–2개와 각주, 12행 표가 들어간다.

| 헤드라인 | 부제 | 본문 | KPI 숫자 | 표 행 | 최소 글자 |
|---|---|---|---|---|---|
| 20pt | 11.5pt | 9.5pt | 24pt | 0.32" | **9pt** |

한 장에 들어가는 요소는 발표용의 약 2배(평균 80개)다. 그래도 **본문 벽 2.39"–6.85"는 지킨다.**

## 2. 만드는 법

```bash
SK=~/.claude/skills/REPORT_PPT
mkdir build && cp $SK/assets/{ksa_mono.js,example_deck.js,ksa_logo.jpg} build/ && cd build
node example_deck.js deck.pptx                      # example_deck.js를 복사해 내용만 교체
python3 $SK/scripts/postprocess.py deck.pptx        # 필수 — 아래 설명
python3 $SK/scripts/check_layout.py deck.pptx --mode report --special 1
```

**`postprocess.py`는 선택이 아니다.** pptxgenjs 4.x가 차트에 *선언하지도 않은 축 참조*를 써 넣어, 그대로 두면 PowerPoint가 **"내용에 문제가 있습니다 / 복구하시겠습니까"** 대화상자를 띄운다. LibreOffice는 조용히 무시하므로 렌더 QA로는 드러나지 않는다. 점검기가 이를 검사하므로 빠뜨리면 FAIL로 막힌다.

`pptxgenjs`는 pptx 스킬 환경에 이미 설치돼 있다(`npm install` 먼저 하지 말 것).

## 3. 표준 골격 (12장 예시)

문서형 표지(문서번호·승인란·목차) → Executive Summary → 진단 개요 → 업무 구조 12행 표 → 절감 경로(워터폴+표 2개) → 요인 분해(트리+표) → 과제 정의서 → 게이트 기준 → 우선순위 평가(매트릭스+평가표) → R&R → 로드맵(간트+분기표) → 지표 정의서.

`assets/example_deck.js`가 이 12장을 그대로 만든다. 복사해 내용만 갈아끼운다.

## 4. 표가 주인공이다

**모든 데이터 표는 `tableNative`(PowerPoint 네이티브)를 쓴다.**

- 머리글은 **가운데 정렬**, 먹 배경에 흰 글자
- **셀 윤곽선을 그리지 않는다** — 머리글 밴드 + 교차 음영(`#FAFAFA`) + 하단 마감선
- 숫자 열은 오른쪽, 구분·주기 등 짧은 값은 가운데, 서술은 왼쪽 정렬
- 강조할 열은 `boldCol`로 지정

네이티브 표는 셀 글이 길면 **행이 자란다.** 헬퍼가 열 폭 대비 줄 수를 미리 추정해 늘어난 높이를 계산하고, 본문 벽을 넘으면 생성을 중단한다. 도식과 x좌표를 맞춰야 하는 표만 `table`(도형)로 남긴다.

## 5. 문서형 장표의 관례

- **표지**에 문서번호·작성부서·검토·승인·개정이력을 표로 넣고 목차를 2열로 배치
- **Executive Summary**를 2쪽에 두고 KPI 6개 + 3열 요약 + 우선 과제 표로 구성
- 표마다 **각주(`footnote`)** 로 산정 기준·제외 조건을 밝힌다
- 각 장 마지막에 **결론 밴드(`callout`)** 를 둔다

## 6. QA

```bash
python3 $SK/scripts/check_layout.py deck.pptx --mode report --special <표지 번호>
python3 /mnt/skills/public/pptx/scripts/office/validate.py deck.pptx
soffice --headless --convert-to pdf deck.pptx && pdftoppm -png -r 78 deck.pdf p   # 전 장표 육안
```

점검기가 잡는 것 — A4 판형, 맑은 고딕 외 폰트(표·차트 내부까지), 9pt 미만, 슬라이드 밖 이탈, 본문 벽 침범(**네이티브 표는 `<a:tr h>` 합산으로 실제 높이 계산** — pptxgenjs는 표 높이를 1.0"로 고정 기재하므로 그 값을 믿으면 안 된다), 5존 앵커 이탈, 하단 30% 공백, **의도하지 않은 검은 윤곽선**, 흐린 글자색, 유채색, 로고 위치·비율·로고 뒤 도형, 이모지, 차트 구조 결함.

**렌더 QA는 반드시 한다.** 밀도가 높을수록 요소가 겹치기 쉽고, 겹침은 좌표 검사로 안 걸린다.

## 7. 자주 하는 실수

- `line: { width: 0 }` — pptxgenjs가 무시하고 1pt `#333333` 선을 그린다. `line: { type: 'none' }`을 쓴다.
- 표 열 폭 합계가 우측 여백 초과 — 헬퍼가 예외를 던진다. `colW` 합계는 `10.3333 − x` 이하.
- 표 아래 콜아웃·각주와 겹침 — 표 반환값 `bottom`으로 다음 요소 y를 잡는다.
- 흰 배경에 `#C7C7C7` 글자 — 최소 `#6B6B6B`.
- 밑줄을 임의 길이로 — `textW()`로 글자 폭에 맞춘다.

## 8. 파일 규칙

- 산출 파일명: `<보고서명>_v<n>.pptx`
- 동봉 자산(로고·모듈)은 수정하지 않는다 — 사본으로 작업
- 차트·표 텍스트는 라이브 텍스트로 유지한다
