# 발표자료 PPT — KSA 하우스 스타일

제안발표·심사PT용 A4 가로 고밀도 발표 덱을 만든다. 정체성은 한 줄로: **모든 본문 장표는 "한 줄 결론 헤드라인 + 라벨·리드문 + 본문 도식 + 경어체 요약 밴드"의 7존 구조를 가지며, 색은 페리윙클·비비드블루·틸 3색 위에 레드 포인트 하나로 위계를 만든다.** 심사위원이 헤드라인과 하단 밴드만 읽어도 스토리가 성립해야 한다.

파일 조작 메커니즘(unzip, add_slide.py, clean.py, validate.py, 렌더 QA)은 **pptx 스킬**의 지침을 그대로 따른다. 본 스킬은 그 위에서 "무엇을(패턴), 어떻게(문법) 채울지"를 정의한다. 새 덱을 pptxgenjs로 백지에서 그리지 말 것 — 슬라이드 규격(A4 가로)과 도식 정밀도, 표 기반 카드 구조를 재현할 수 없다. 반드시 assets/patterns.pptx에서 복제해 조립한다.

## 2. 장표 문법 (7-Zone)

모든 본문 장표(패턴 P3~P30)는 일곱 구역으로 구성된다. ①~④·⑦의 프레임 도형은 패턴 슬라이드에 이미 배치되어 있으므로 **텍스트만 교체**한다:

1. **브레드크럼** (0.59, 0.59): `N. 대목차` 검정 + `· 소제목` #1040C3, 12pt HY헤드라인M. 대목차는 목차 장의 항목과 일치시킨다.
2. **상단 분리바** (y≈1.41): 좌 검정 6.1cm + 우 #002060 19.98cm — 레이아웃 소속, 건드리지 않음.
3. **헤드라인** (0.73, 1.71, 26.09×1.03): 18pt HY헤드라인M 중앙정렬, 한 줄. 이 장표의 결론이다. §3 작법 참조.
4. **밑줄바** (y≈2.89): 좌 #5D6DBE + 우 검정 — 레이아웃 소속, 건드리지 않음.
5. **라벨 + 리드문** (y=3.66, 높이 1.36): 좌측 #262626 박스에 흰 16pt HY헤드라인M 라벨(예: 추진 배경, 사업목표, 수행 고도화). 우측 #F8F8F8 박스에 12pt 굵은 맑은 고딕 리드문 2줄 — 본문 도식을 한 문단으로 요약하는 개조식("~함", "~을 보장").
6. **본문 도식** (y≈5.2~16.6): 1장표 1메시지. 패턴 카탈로그에서 선택. 도식 위 소섹션 제목은 "파란 체크 아이콘(0.47cm) + 10.5pt 굵게" 그룹을 재사용.
7. **하단 요약 밴드** (0.59, 16.65, 26.09×1.38, #D7EAF8): 13pt 굵게 중앙, 1~2줄. **경어체 결론** — "~합니다.", "~하겠습니다." §3 참조. 그 아래 페이지 번호 `- N -`.

**밀도 원칙.** 이 스타일은 심사위원이 읽는 고밀도형이다. 본문 도식은 존을 꽉 채워 완성한다: 카드·박스에는 불릿 2~4개(각 1~2줄), 내용이 부족하면 근거·수치를 보강하거나 박스 수를 줄여 높이를 키우고, 넘치면 문장 압축 → 불릿 분할 → 장표 분할 순으로 해결한다. 박스 밖으로 나간 텍스트, 듬성하게 빈 박스 모두 미완성이다. 라벨·구조 도형은 자기가 묶는 블록 전체 높이에 맞춘다.

## 3. 헤드라인·요약 밴드 작법

**헤드라인 (Zone 3)** — 명사구 결론형 한 줄. 세 가지 정형:
- 대비·전개형: `A → B → C 원칙 중요` (화살표로 인과 압축)
- 정의형: `주어 : 수식어 핵심 개념` (콜론으로 주제 선언, 예: "C.A.R.E. 전략 : 진단부터 이행까지 끊김 없는 현장 밀착형 고객감동 실현")
- 합성형: `요소 + 요소 + 요소의 결과` (예: "검증된 경험 + 우수 전문가 + 전국 네트워크")

색 강조 규칙: 기본 검정. **핵심 개념·강점 구절은 #1040C3 또는 #5D6DBE**, **위기·차별화·승부 구절은 #E35740**. 한 헤드라인에 강조 2개(파랑 1 + 빨강 1)까지. 전부 칠하면 아무것도 강조되지 않는다.

**요약 밴드 (Zone 7)** — 헤드라인이 "무엇"이면 밴드는 "그래서 우리가 이렇게 하겠다"이다. 경어체 완결문 1~2줄: "~을 제공합니다.", "~을 약속합니다.", "~하겠습니다." 수치 화살표 체인도 좋다: "390개 기업 발굴 → 300건 컨설팅 → 75건 정책 연계 → 80% 고용 유지로 …를 확립합니다." 헤드라인(개조식·명사구)과 밴드(경어체·완결문)의 문체 대비를 유지할 것 — 리드문(Zone 5)은 개조식 "~함"으로 끝난다.

헤드라인만 이어 읽어도, 밴드만 이어 읽어도 각각 발표 전체 스토리가 성립해야 한다.

## 4. 발표 덱 표준 골격

표지(P1) → 목차(P2) → **목차 항목별 본문 블록**(항목당 3~7장, 브레드크럼 번호 일치) → 클로징(P31).

제안발표 덱의 검증된 골격(원본 31장): ①사업계획의 적정성(배경→필요성→성공요인→비전→목표→추진체계→전략→수요발굴→수행→진단→일정→성과관리) ②사업수행능력(기관현황→차별화 역량→전문인력) ③정책연계·지원계획 ④인적자원 투자계획 ⑤유관기관 협업. 다른 유형(성과보고·사업설명회)도 "왜(배경) → 무엇을(전략·계획) → 누가(역량·체계) → 어떻게 믿나(실적·품질)" 리듬에서 필요한 블록만 발췌해 쓴다.

각 본문 블록 안에서는 개관(비전·프레임워크 1장) → 상세(n장) → 보증(실적·품질 1장) 순서를 지키고, 표형·카드형·프로세스형 패턴을 섞어 리듬을 만든다. 같은 패턴 연속 2장까지(비교표 시리즈 제외).

## 6. 제작 워크플로

1. **스토리라인 먼저**: 목차(대목차 3~5개) → 장표별 헤드라인 → 장표별 요약 밴드 문장을 텍스트로 먼저 설계한다(§3·§4). 사용자 확인이 가능하면 이 단계에서 확인받는다.
2. **패턴 매핑**: 장표마다 P번호를 배정한다. 근거 데이터가 없는 차트·수치는 만들지 않는다(가짜 수치 금지) — 수치 없는 주제는 카드·프로세스형 패턴으로.
3. **조립**: patterns.pptx를 언팩 → 필요한 패턴을 add_slide.py로 복제·배열 → 안 쓰는 원본 슬라이드는 sldIdLst에서 제거 → clean.py.
4. **내용 교체**: 브레드크럼·헤드라인·라벨·리드문·본문·요약 밴드 순으로 교체. 템플릿 슬롯 수와 실제 항목 수가 다르면 남는 그룹(도형+텍스트)이나 표 행·열을 통째로 삭제한다(카탈로그의 가감법 참조). **원본의 KSA·G-DAX 고유 문구, 인명·직책, 기관 로고·스크린샷 이미지가 남지 않도록** 전수 교체·삭제한다.

   **XML 삽입 순서 규칙 — 어기면 PowerPoint가 "파일 손상, 복구" 프롬프트를 띄운다** (LibreOffice·validate.py는 통과하므로 QA에서 안 잡힌다):
   - 새 런(`<a:r>`)은 반드시 `<a:endParaRPr>` **앞**에 넣는다. 빈 문단(pPr+endParaRPr만 있는 문단, 특히 표 헤더 셀)에 텍스트를 넣을 때 endParaRPr 뒤에 붙이는 실수가 가장 흔하다.
   - `<a:rPr>`·`<a:defRPr>`·`<a:endParaRPr>`의 자식은 스키마 순서를 지킨다: `ln → (no|solid|grad|blip|patt|grp)Fill → effectLst → highlight → uLn계 → uFill계 → latin → ea → cs → sym → hlink계 → extLst`. 색을 바꾸려고 `<a:solidFill>`을 `<a:latin>` 뒤에 붙이면 위반이다.
   - 표 행(`<a:tr>`)에 셀을 추가할 때 새 `<a:tc>`는 `<a:extLst>` **앞**에 넣는다.
5. **문서 속성**: 작성자·최종 저장자 = 사용자 지정값(기본 "전봉관"), 제목 = 발표명. 산출 파일에 도구 흔적(python-pptx 등)을 남기지 않는다.
6. **QA**: 압축 전에 반드시 두 스크립트를 실행한다:
   ```bash
   python scripts/fix_order.py <unpacked>/        # 4번 순서 규칙 위반 자동 교정 (0건이어야 정상)
   python scripts/strip_thinkcell.py in.pptx out.pptx   # think-cell 잔재·공유 파트·협업 흔적 제거 (완성본에 1회)
   ```
   fix_order.py가 0건이 아니면 교체 로직이 순서 규칙을 어긴 것이니 원인을 고친다. 이후 pptx 스킬의 QA 절차(렌더 → 전 장표 육안 → validate.py `--original assets/patterns.pptx`). validate.py 통과가 PowerPoint 통과를 보장하지 않음을 기억할 것 — 순서 위반은 fix_order.py만 잡는다. §7의 렌더 특성을 먼저 읽을 것.

## 7. QA 시 렌더 특성 (오탐 주의)

- **표 헤더(#1040C3)의 흰 텍스트가 LibreOffice 렌더에서 누락돼 보인다.** 빈 파란 박스는 markitdown 텍스트 덤프나 XML로 실제 텍스트 존재를 확인하라 — 실제 PowerPoint에서는 정상 표시된다. 반대로, 렌더에 안 보인다고 헤더 텍스트 교체를 건너뛰면 KSA 문구가 잔존한다.
- **HY헤드라인M은 임베드되어 있지 않다.** QA 렌더는 대체 폰트로 그려지므로 헤드라인 폭 판정이 부정확하다 — 헤드라인은 26.09cm 박스에 한 줄 기준 공백 포함 42자 안팎까지만 쓰고, 렌더상 두 줄이면 실제로도 길다고 보고 압축한다. 사용자 PC에는 폰트가 있으므로 서체를 바꾸지 말 것.
- 표지 제목(32pt)은 2줄까지 안전. 3줄이 되면 아래 기관명과 겹친다(원본 P1이 실제로 겹쳐 있음 — 교체 시 반드시 2줄 이내로).
- 잔존 문구 그렙: `markitdown out.pptx | grep -E "KSA|G-DAX|한국표준협회|표준협회|강수영|Ask KSA"` 결과가 있으면 미완성. (사용자가 KSA 소속으로 그 문구를 요청한 경우는 예외.)
