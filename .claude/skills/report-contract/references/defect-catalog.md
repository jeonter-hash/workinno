# AI 보고서 결함 카탈로그와 스킬 개선안 v1

작성 2026-08-25 · 대상 KOFICE 경영관리체계 고도화 결과보고서 제작(v5.2, 본문 152장) 전 과정
용도 `report-ppt` 스킬 및 보고서 발주 프롬프트 개선

---

## Ⅰ. 결론

**AI가 만든 보고서가 무너지는 원인은 지식 부족이 아니라 계약 부재다.**

지금까지의 지시는 **무엇을 쓸지**(주제·자료)만 주었고, **어떤 논리 단위로 쓸지**(구조 계약)와 **무엇을 하면 불합격인지**(금지·게이트)를 주지 않았다. 그 결과 세 가지가 반드시 일어난다.

| 계약이 빠진 자리 | 모델이 하는 일 | 산출물에 나타나는 증상 |
|---|---|---|
| 논리 단위가 정해지지 않음 | **최소저항 경로인 열거로 붕괴** | 세부 항목이 나열만 됨. 프레임 없이 항목이 늘어섬 |
| 미결정과 확정의 구분이 없음 | **빈칸을 임의 확정으로 메움** | 부서 의견을 검토도 않고 한 안을 확정 서술 |
| 합격 조건이 없음 | **자기검증 없이 제출** | 버전만 늘고 같은 결함이 되풀이됨 |

여기에 이번 세션에서 새로 드러난 네 번째가 있다.

| 계약이 빠진 자리 | 모델이 하는 일 | 증상 |
|---|---|---|
| 제작 용어와 산출물 문안의 경계가 없음 | **제작 규칙을 문안에 그대로 옮겨 씀** | 「모든 절은 4대 기준 중 하나 이상을 판정 기준으로 선언하고…」, 「읽는 경로」 |

이 네 가지를 계약으로 못박는 것이 스킬 개선의 골자다.

---

## Ⅱ. 근본 원인 세 가지

### 원인 1 — 구조 계약의 재귀 적용이 없다
3부 구조(프레임 → 적용 → 결론)를 **보고서 전체에만** 지시하고 부·절·장표에 재귀로 계약하지 않으면, 하위 계층은 반드시 열거로 무너진다. 상위에서만 지켜지고 하위에서 깨지는 것이 전형적인 실패 모양이다.

### 원인 2 — 확정과 미확정을 가르는 규칙이 없다
모델은 공백을 싫어한다. 「[미확정] 표기를 허용하고 권장한다」가 없으면 반드시 하나를 골라 단정한다. KOFICE 사례에서 전략목표 Ⅲ이 부서 의견(인력양성) 검토 없이 조사·연구로 확정된 것이 그 결과다.

### 원인 3 — 제작 언어와 산출물 언어가 섞인다
설계서에서 쓰는 말(프레임장·소결장·접기·배치 단위)이 장표 제목과 본문에 그대로 나온다. 독자는 이것을 **AI가 자기 작업을 설명하는 소리**로 읽는다. 이 한 가지가 「AI가 마구잡이로 만든 보고서」라는 인상의 가장 큰 원인이다.

## Ⅲ. 결함 카탈로그 D1~D16

각 항목은 **증상 → 원인 → 처방 → 검출**로 적는다. 검출란은 자동 점검기에 넣을 규칙이다.

### D1. 나열 붕괴
- **증상** 판단기준·절차 제시 없이 항목만 열거. 「현황」·「주요 내용」·「검토 결과」류 소제목.
- **원인** 계층별 구성 슬롯이 지정되지 않음.
- **처방** 절은 `프레임장 1 + 적용결과장 2~5 + 종합장 1`로 **슬롯을 고정**한다. 분량을 「20장」이 아니라 슬롯 수로 지정한다.
- **검출** 한 절에 프레임 성격 장이 없거나 종합 장이 없으면 불합격.

### D2. 임의 확정
- **증상** 미결정 안건을 확정 사실로 서술. 부서 의견이 대안 목록에서 누락.
- **원인** 결정 안건 목록과 처리 규격이 프롬프트에 없음.
- **처방** 미결정 안건은 **5슬롯 규격**으로만 작성 — ① 쟁점 정의 ② 대안 병렬(전건 등재) ③ 평가기준 3~5 ④ 기준×대안 매트릭스 ⑤ 선정안과 **미채택 사유**. 부서 의견 누락은 불합격 사유로 선언한다.
- **주의** 보고서에는 **결정 안건·결정 요청·결정란을 넣지 않는다.** 대안 병렬 → 매트릭스 → 선정 판단과 미채택 사유까지가 컨설팅 산출물의 형태다.
- **검출** 「결정: ___」, 「결정 요청」, 「의사결정 안건」 문자열.

### D3. 메타 표현 — 제작 규칙의 문안 유출 ★최다
- **증상** 「모든 절은 4대 기준 중 하나 이상을 판정 기준으로 선언하고, 그 기준을 적용한 결과와 소결을 같은 절 안에서 닫음」, 「읽는 경로」, 「수록 장」, 「본 보고서는 3부로 구성」, 「근거 ①(4장)」.
- **원인** 제작 언어와 산출물 언어의 경계가 계약에 없음.
- **처방** **보고서는 자기 자신을 말하지 않는다.** 서술 대상은 과업과 기관뿐이다. 제작 용어는 설계서에만 남긴다.
- **검출** 아래 M1~M7 정규식(Ⅳ장 코드).

### D4. 학술·정책연구 보고서 용어
- **증상** 「소결」, 「접다/접는 규칙/기능 접기」.
- **원인** 컨설팅 문서의 관용 표기를 확인하지 않음.
- **처방** **절 마무리 = 「○○ 종합」 / 부 마무리 = 「○○ 결론」**으로 층위를 이름으로 가른다. 「접기」류 비유는 「통합 / 통합 기준 / 핵심 기능 도출 기준」으로 바꾼다. 같은 절에 종합 성격 장이 여럿이면 절 마무리 장에만 「종합」을 남긴다.
- **검출** `소결|접는 규칙|기능 접기|접어|접음`

### D5. 문어체·구어체·비유 서술어
- **증상** 갈래 / 밀림 / 얹다 / 닿다 / 갈리다 / 굳어지다 / 뼈대 / ~하기 이름.
- **원인** 문장을 부드럽게 하려다 격을 낮춤.
- **처방** **한자어 명사형을 쓰고 순우리말 비유를 피한다.**

| 쓰지 않음 | 쓴다 |
|---|---|
| 세 갈래 / 네 갈래 | 3대 / 4대 · 세 가지 / 네 가지 |
| ~에서 밀림 | ~에서 뒤처짐 |
| A에 B를 얹다 | A에 B를 대응시키다 |
| ~에 닿다 / 닿지 않다 | ~로 이어지다 / 미치다 |
| 갈리다 / 갈려 | 나뉘다 / 달라지다 / 다르다 |
| 굳어지다 | 고착되다 |
| 뼈대 | 틀 |
| ~하기 이름 | ~하기에는 이른 단계 |

- **검출** `갈래|밀림|얹어|얹은|닿지|닿음|(?<!엇)갈림|(?<!엇)갈려|굳어|뼈대` — 「엇갈리다」는 표준어이므로 제외한다

### D6. 수사 표기 ★가장 자주 어김
- **증상** 「석 달」, 「한 해 뒤」, 「세 해 잇달아」, 「마흔여덟 개」, 「스물두 건」, 「여섯 영역」, 「첫 해」.
- **원인** 순우리말 수사가 자연스럽다고 오판. 공공기관 보고서 관행과 어긋남.
- **처방** 경계선은 **세는 행위가 있느냐**다. 값은 숫자로, 이름은 말로 쓴다.

| 구분 | 규칙 | 예 |
|---|---|---|
| **기간·연차** | 반드시 한자어 | 석 달 → **3개월** / 한 해 → **1년** / 세 해 잇달아 → **3개년 연속** |
| **단위 명사가 붙는 수**(건·개·명·점·팀·곳·회) | 아라비아 숫자 | 네 건 → **4건** / 스물두 건 → **22건** / 세 곳 → **3곳** / 두 팀 → **2개 팀** |
| **6 이상** | 아라비아 숫자 + 단위 | 여섯 영역 → **6개 영역** / 여덟 기능 → **8개 기능** |
| **1~5 순수 관형사**(단위 없이 명사 수식) | 순우리말 허용 | 네 축 · 세 기준 · 두 가지 · 네 가지 |
| **묶음 명칭** | 「N대 ○○」 | 3대 공백 · 4대 판단기준 · 4대 전환 유형 |
| 맞춤법 | 첫 해 → **첫해**(또는 1차년도) | |

- **검출** `석 달|한 해|세 해|두 해|잇달아|마흔|서른|쉰두|여든|스무|열두|열세|열다섯|여섯 개|여덟 개|첫 해`

### D7. 과업 범위 이탈
- **증상** 과업 범위가 아닌 항목이 결과물처럼 서술됨(개인 성과 연계 제도 설계).
- **원인** 범위 경계가 계약에 없음.
- **처방** 프롬프트에 **범위 경계를 명시**한다. KOFICE 사례 — 설계 범위는 성과지표 개선(목표치 설정기준 포함)까지. **개인 성과 연계는 필요성 확인과 직원 의견 수렴까지만.** 직무중심 보수체계·성과급 지급률·조직 개편은 범위 밖.
- **검출** 범위 밖 키워드 목록을 프로젝트마다 정의해 스캔.

### D8. 과업 목적란의 확정 결과물
- **증상** 목적란에 「12개 전략과제」, 「대표 계량지표 5개」 같은 확정 수치·명칭이 들어감 → **이미 답을 정해 놓은 것처럼** 읽힘.
- **처방** 과업 목적란에는 **「산출물의 형태」**를 쓴다. 확정 수치와 명칭은 본문 결과에서만 쓴다.
- **검출** 개요 부(Ⅰ부) 목적 슬라이드에 숫자+단위가 등장하면 경고.

### D9. 근거 연결 끊김
- **증상** 새 자료를 추가했는데 판정표·종합·SWOT 등 하류가 그대로.
- **원인** 자료 추가가 국지 편집으로 끝남.
- **처방** **자료를 추가하면 하류까지 함께 고친다.** 추가 → 판정표 행 수 갱신 → 종합 문장 갱신 → SWOT O/W/T 갱신 → 부 결론 갱신의 연쇄를 한 작업 단위로 묶는다.
- **검출** 「N개 요인」 같은 개수 표기가 장마다 다르면 경고.

### D10. 분석 단위 불일치
- **증상** 앞 장은 3개 사업 단위, 뒤 장은 2개 사업 단위로 근거 없이 바뀜.
- **처방** **앞뒤 장의 분석 단위가 바뀌면 잇는 장을 둔다.** 3→2 매핑표와 재편 기준을 한 장으로 명시.
- **검출** 같은 절 안에서 단위 명사(사업·부문·구분)의 개수가 달라지면 경고.

### D11. 없는 수치의 창작
- **증상** 기초선이 없는 신설 지표에 목표치를 만들어 넣음. 원자료에 없는 명칭을 지어냄.
- **처방** **없는 수치는 만들지 않는다.** 「기준값 설정」·「미측정」·「미집계」로 적고, 산출근거란에 설정 방식을 쓴다. 이름을 모르는 항목은 표에서 빼고 각주로 사유를 남긴다.
- **검출** 원천 파일에 없는 숫자가 본문에 나오면 불합격. 근거 추적을 장 번호별로 요구하면 창작이 줄어든다.

### D12. 배치 정합 결함 — 자원과 주관의 어긋남
- **증상** 예산 60%를 쓰는 기능의 담당 팀에 주관 과제가 0건.
- **원인** 「축마다 과제 3개」 같은 **근거 없는 대칭 규칙**을 자원 정합보다 앞세움.
- **처방** ① **주관 0건인 사업팀이 생기면 배치 오류로 본다.** ② 과제 수는 축의 중요도가 아니라 **자원 규모**를 따른다. ③ 전략과제를 더하거나 옮길 때마다 부서 연계표를 다시 계산한다.
- **검출** 부서×주관 교차표에서 0인 사업팀 존재 여부.

### D13. 과제 급(級) 판정 부재
- **증상** 수단의 효율을 재는 개선 활동(행정절차 간소화)이 전략과제로 올라감.
- **처방** **전략과제 판정 4기준**을 계약에 넣는다.

| 기준 | 확인 |
|---|---|
| 근거 | 법 조문 또는 상위계획 과제에 직접 대응하는가 |
| 자원 | 예산·인력이 배정되거나 배정 예정인 독립 단위인가 |
| **성과** | **축의 목적을 직접 재는 지표**를 둘 수 있는가 (수단의 효율이 아니라 목적의 달성) |
| 소관 | 주관 부서가 하나로 정해지는가 |

**기준 3이 결정적이다.** 소요 기간 단축은 다른 과제의 수단이므로 전략과제가 아니다. 급을 낮추는 것과 지표를 버리는 것은 다르다 — 강등하되 지표는 상위 과제로 승계한다.

### D14. 산출물 완결성 결여
- **증상** 신규 항목만 정의서가 있고 나머지는 목록 수준. 양식을 바꾸면서 담당 열이 사라짐.
- **처방** **같은 성격의 항목은 전건이 같은 서식을 갖춘다.** 양식을 바꿀 때는 **바뀌기 전 서식의 정보 항목을 대조표로 확인**하고, 빠지는 항목이 있으면 어디로 옮겼는지 적는다.
- **검출** 동일 유형 슬라이드의 표 열 구성이 서로 다르면 경고.

### D15. 제목·머리글 어미 ★낱말 교체로는 안 잡힘
- **증상** 표 머리글과 패널 제목이 문장 조각으로 끝남 — 「확인한 것」, 「마련한 것」, 「손에 쥐어야 할 것」, 「그것이 없으면」, 「아직 정해지지 않은 것」, 「무엇을 적는가」, 「점검을 가볍게 두는 이유」, 「설계가 미치지 않는 부분」, 「상위 3층은 손대지 않는다」.
- **원인** 금지 사전을 낱말 단위로만 만들어 **어미 유형**을 잡지 못함.
- **처방** **머리글과 제목은 항목의 이름이지 문장이 아니다. 반드시 명사구로 끝난다.** 확인한 것 → 진단 결과 / 마련한 것 → 개선 방안 / 손에 쥐어야 할 것 → 필수 산출물 / 그것이 없으면 → 미확보 시 영향 / 무엇을 적는가 → 기술 내용 / ~이유 → ~근거 / ~부분·곳·지점 → ~영역·부서·접점.
- **허용** 관형절이 붙어도 명사구로 끝나면 된다 — 「확인된 사실」, 「다음 단계에 미치는 영향」, 「고착되는 위험」.
- **검출** `것$|는가$|으면$|이유$|곳$|부분$|지점$|모습$|쓰임$` 를 `head:[...]`·`title:'...'` 에만 적용.

### D16. 「설계」의 오용
- **증상** 목적어 없이 홀로 쓰인 「설계」가 과업 산출물 전체를 가리킴 — 「설계 결론」, 「설계 요약」, 「설계 내용」, 「설계는 갖추어졌으므로」.
- **원인** ① **과업명과 어긋남** — 과업명이 「~ 재수립 및 ~ 고도화」인데 산출물을 「설계」라 부르면 다른 과업처럼 읽힘 ② **「설계」는 엔지니어링·건축의 말** — 설계 다음에 시공이 오지만, 컨설팅은 산출물이 **개선 방안**이고 다음이 **이행**임.
- **처방** **목적어가 붙은 「제도 설계」·「지표 설계」·「산식 재설계」는 그대로 쓴다.** 홀로 쓰인 것만 바꾼다 — 설계 결론 → **과업 결론** / 설계 요약 → **개선 방안 요약** / 설계 내용 → **개선 방안** / 설계 범위 → **과업 범위** / 후속 설계 → **후속 과제**.
- **검출** `설계` 앞 2어절에 명사 목적어가 없으면 경고.

## Ⅵ. `report-ppt` 제작 함정 체크리스트

이번 152장 제작에서 실제로 걸린 것만 적는다.

### 좌표·치수
- 표 `colW` 합계 **≤ 9.8333"** (x=0.5 기준). 넘으면 빌드 실패.
- 패널 최소 높이 = `0.46(제목) + 항목수 × 줄높이 + 2 × pad`. 항목 1개면 0.88", 3개면 약 1.40".
- 표 아래 결론 밴드를 두면 `t.bottom ≤ BB − 0.42`.
- 본문에 **0.7" 이상 빈 띠**가 남으면 경고 — rowH를 키우거나 패널로 채운다.
- **10행 표는 rowH 0.32 이하**, 12행 간트는 rowH 0.30이어야 아래 패널이 들어간다.
- `gantt()`의 반환값은 **객체가 아니라 숫자**다. `g.bottom`이 아니라 `g`를 쓴다.

### 서식
- 헤드 타이틀 **콜론 금지, 30자 이하**. 넘치면 짧은 이름 필드를 따로 둔다.
- 표 셀에 `—`를 쓰면 흐린 글자색 경고 — **빈 문자열이나 실제 낱말**('없음'·'해당 없음'·'미측정')을 쓴다.
- `kpiRow`에 `dark:true` 금지(라벨 대비 경고).
- 누적 막대 금지(무채색에서 라벨이 안 읽힘). 단일 계열이나 묶은 막대를 쓴다.
- 소수점은 `fmt:'0.0'`을 반드시 준다. 없으면 4.64가 5로, 92.6이 93으로 렌더된다.
- 음수 막대는 절댓값으로 그리고 라벨에 「~보다 낮은 폭」을 적는다.
- 간지 로마숫자는 `K.g2` 이상(K.g4는 흐림 경고).
- **결론 밴드는 항상 가운데 정렬** — `callout`의 txt에 `align:o.align||'center'` 패치.

### 밀도
- **표가 본문의 65%를 넘는 장이 절반을 넘으면 deck 경고.** 차트·체브론·패널을 섞는다.
- 표가 80%를 넘으면 So-What 패널 2개를 붙인다.

### 빌드 운영
- 새 배치는 재빌드 스크립트에 **출력 파일명 인자를 반드시 준다**(빈 문자열이면 스캔 실패).
- `rm -f *.png`가 `photo_placeholder.png`를 지운다 — 표지 빌드가 깨진다.
- `firstSlideNum` 주입 시 heredoc 이스케이프 주의(`\"42\"`는 XML을 깨뜨림).
- 장수가 바뀌면 **이후 모든 배치의 firstSlideNum을 다시 계산**한다.
- 문서 속성 Author·Last saved by를 최종 치환하고 도구명(pptxgenjs 등)을 남기지 않는다.
