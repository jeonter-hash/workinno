# 보고서 논리·문안 계약

## 0. 이 스킬이 푸는 문제

**AI가 만든 보고서가 무너지는 원인은 지식 부족이 아니라 계약 부재다.**

지시가 **무엇을 쓸지**(주제·자료)만 주고 **어떤 논리 단위로 쓸지**와 **무엇이 불합격인지**를 주지 않으면 반드시 네 가지가 일어난다.

| 빠진 계약 | 모델의 행동 | 증상 |
|---|---|---|
| 논리 단위 미지정 | **최소저항 경로인 열거로 붕괴** | 프레임 없이 항목만 늘어섬 |
| 확정/미결정 구분 없음 | **빈칸을 임의 확정으로 메움** | 부서 의견을 검토 없이 배제하고 한 안을 단정 |
| 합격 조건 없음 | 자기검증 없이 제출 | 버전만 늘고 같은 결함 반복 |
| 제작·산출물 언어 경계 없음 | **제작 규칙을 문안에 옮겨 씀** | 「읽는 경로」, 「판정 기준으로 선언」 |

네 계약을 §1~§4에 둔다. 위반 사전과 사례는 `references/defect-catalog.md`, 교체표는 `references/ban-dictionary.md`, 조판 함정은 `references/build-traps.md`에 있다.

## 1. 구조 계약 — 3계층 재귀

**발주 프롬프트 상단에 그대로 붙인다.** 3부 구조를 보고서 전체에만 지시하고 부·절·장표에 재귀로 계약하지 않으면 하위 계층은 반드시 열거로 무너진다.

```
[구조 계약 — 모든 계층에 재귀 적용]
보고서·부·절·장표 어느 계층에서든 3부 구조가 성립해야 한다.
  ① 프레임/절차 제시 → ② 그 프레임을 적용한 결과 → ③ 결론·시사점

계층별 구성 슬롯(고정):
- 부  : [부 도입 1장: 수행 프레임·절차·산출물 정의] + [절 n개] + [부 결론 1장]
- 절  : [절 프레임 1장: 판단기준·절차·투입자료] + [적용 결과 2~5장] + [종합 1장]
- 장표: [메시지 = 이 장의 결론 1문장] + [본문 = 프레임 적용 도식 1개] + [근거 표·수치]

상향 정합:
- 장표 메시지는 소속 절 종합의 근거여야 한다.
- 절 종합은 소속 부 결론의 근거여야 한다.
- 상위 결론에 연결되지 않는 내용은 삭제하거나 부록으로 이관한다.

금지:
- 판단기준·절차 없이 항목만 열거하는 장표
- '현황' '주요 내용' '검토 결과' 류의 나열형 소제목
- 종합 없이 다음 절로 넘어가는 구성
- 결론을 마지막 장에만 몰아두는 구성
```

**부정 지시보다 슬롯 지정이 강하다.** 「나열하지 마」보다 「프레임장·결과장·종합장 세 종류만 만들어라」가 훨씬 잘 지켜진다. 분량은 「20장」이 아니라 **슬롯 수**로 준다.

## 2. 문안 언어 계약

**보고서는 자기 자신을 말하지 않는다.** 이 한 가지가 「AI가 마구잡이로 만든 보고서」라는 인상의 가장 큰 원인이다.

```
[문안 언어 계약]
1. 서술 대상은 과업과 기관뿐이다. 제작 용어(프레임장·적용장·소결장·배치 단위)는
   설계서에만 쓰고 산출물 문안에 등장시키지 않는다.
2. 절 마무리는 「○○ 종합」, 부 마무리는 「○○ 결론」으로 이름을 달리한다.
   같은 절에 종합 성격 장이 여럿이면 절 마무리 장에만 「종합」을 남긴다.
3. 한자어 명사형을 쓰고 순우리말 비유를 피한다.
   금지: 소결 · 접다 · 갈래 · 밀림 · 얹다 · 닿다 · 갈리다 · 굳어지다 · 뼈대
4. 수사 표기 — 값은 숫자로, 이름은 말로.
   - 기간·연차는 한자어: 3개월 · 1년 · 3개년 연속   (석 달·한 해·세 해 금지)
   - 단위 명사(건·개·명·점·팀·곳·회)가 붙으면 아라비아 숫자: 4건 · 22건 · 3곳 · 2개 팀
   - 6 이상은 아라비아 숫자 + 단위: 6개 영역 · 8개 기능 · 12개 과제
   - 1~5의 순수 관형사만 순우리말: 네 축 · 세 기준 · 두 가지
   - 묶음 명칭은 「N대 ○○」: 3대 공백 · 4대 판단기준
   - 첫 해 → 첫해(또는 1차년도)
5. 없는 수치는 만들지 않는다. 「기준값 설정」·「미측정」·「미집계」로 적고
   설정 방식을 산출근거란에 쓴다. 이름을 모르는 항목은 표에서 빼고 각주로 사유를 남긴다.
6. 과업 목적란에는 확정 수치·명칭이 아니라 「산출물의 형태」를 쓴다.
   확정 결과물을 목적란에 쓰면 이미 답을 정해 놓은 문서로 읽힌다.
```

## 3. 미결정 안건 5슬롯

모델은 공백을 싫어해 반드시 하나를 골라 단정한다. **「[미확정] 표기를 허용하고 권장한다」를 명시**해야 임의 확정이 줄어든다.

```
[미결정 안건 처리 규칙]
아래는 미결정 안건이다. 특정 안을 확정 사실로 서술하지 말 것.
  - 안건 1: (…) — 후보안 A / B / C
미결정 안건은 5슬롯 규격으로만 작성한다.
  ① 쟁점 정의(1문장) ② 대안 병렬(전건 등재, 하나라도 누락 금지)
  ③ 평가기준 3~5개와 기준별 근거 ④ 기준×대안 매트릭스
  ⑤ 선정 판단과 미채택 사유
부서·현업 의견은 반드시 대안으로 등재한다. 누락은 불합격 사유다.
보고서 본문에는 결정 요청·결정란·의사결정 안건을 넣지 않는다.
(컨설팅 산출물의 형태는 대안 병렬 → 매트릭스 → 선정 판단과 미채택 사유까지다.)
```

## 4. 자기검증 게이트 G1~G9

**산출물과 함께 이 표를 채워 제출한다. 표가 없으면 산출물을 받지 않는다.**

```
G1 구조 : 부/절/장표 각 계층에 프레임·적용·결론이 모두 있는가 (없는 절 번호)
G2 정합 : 상위 결론에 연결되지 않는 장표가 있는가 (장 번호)
G3 나열 : 판단기준 없이 열거만 한 장표가 있는가 (장 번호)
G4 결정 : 미결정 안건을 단정 서술한 곳이 있는가, 대안 누락은 없는가
G5 근거 : 수치·인용의 원천 파일명과 위치를 장 번호별로 제시할 수 있는가
G6 미해결 : 확정 불가로 남긴 항목과 사유
G7 문안 : scripts/meta_check.py 전 규칙 0건인가
G8 범위 : 과업 범위 밖 항목이 결과물처럼 서술되지 않았는가
G9 배치 : 자원을 쓰는 단위에 주관이 비어 있지 않은가
하나라도 미충족이면 제출하지 말고 먼저 무엇이 부족한지 보고한다.
```

## 5. 분할 발주

**한 번에 한 게이트만 발주한다. 통짜 생성은 구조 붕괴의 주요 원인이다.**

| 게이트 | 발주 | 승인 기준 |
|---|---|---|
| G-A 골격 | 부/절/장표 3계층 개요 + 프레임·종합 문장만(내용 없이 논리만) | 종합만 이어 읽어도 스토리가 성립 |
| G-B 절 본문 | 절 1개씩 | 3부 구조·상향 정합 충족 |
| G-C 미결정 | 5슬롯 문서 | 대안 전건 등재·미채택 사유 명시 |
| G-D 장표 | PPT 변환(`/report-ppt` 문서형 · `/present-ppt` 발표형) | 서식 점검기 0 FAIL |
| G-E 검증 | doc-audit · urimal-review · meta_check | 논리·수치·문체 통과 |

## 6. 자동 점검

```bash
python3 scripts/meta_check.py 산출물.pptx [산출물2.pptx …]
```

M1~M8(메타·결정 요청) + S1~S3(학술 용어·구어체·수사 표기) 규칙으로 전체 텍스트를 스캔한다. **전 규칙 0건이 제출 조건**이다. 프로젝트마다 범위 밖 키워드를 `RULES`에 추가한다.

## 7. 설계 판단 규칙 — 과제 체계를 다룰 때

전략과제·실행과제 같은 위계를 설계할 때 되풀이되는 두 가지 오류를 막는다.

**전략과제 판정 4기준** — 넷 중 셋 이상 충족해야 전략과제다.

| 기준 | 확인 |
|---|---|
| 근거 | 법 조문 또는 상위계획 과제에 직접 대응하는가 |
| 자원 | 예산·인력이 배정되거나 배정 예정인 독립 단위인가 |
| **성과** | **축의 목적을 직접 재는 지표**를 둘 수 있는가 (수단의 효율이 아니라 목적의 달성) |
| 소관 | 주관 부서가 하나로 정해지는가 |

**기준 3이 결정적이다.** 소요 기간 단축·절차 간소화는 다른 과제의 수단이므로 전략과제가 아니다. 급을 낮추되 **지표는 상위 과제로 승계**한다 — 급을 낮추는 것과 지표를 버리는 것은 다르다.

**자원-주관 정합** — ① 자원(예산·사업)을 가장 많이 쓰는 단위에 **주관이 0건이면 배치 오류**다. ② 과제 수는 축의 중요도가 아니라 **자원 규모**를 따른다. 「축마다 3개」 같은 대칭은 근거 없는 편의 규칙이므로 자원 정합에 양보한다. ③ 과제를 더하거나 옮길 때마다 부서 연계표를 다시 계산한다.

## 8. 갱신 규칙

- **자료를 추가하면 하류까지 함께 고친다.** 추가 → 판정표 행 수 → 종합 문장 → SWOT → 부 결론의 연쇄를 한 작업 단위로 묶는다.
- **앞뒤 장의 분석 단위가 바뀌면 잇는 장을 둔다.** 3→2 매핑표와 재편 기준을 한 장으로 명시한다.
- **같은 성격의 항목은 전건이 같은 서식을 갖춘다.** 양식을 바꿀 때는 이전 서식의 정보 항목을 대조하고, 빠지는 항목이 있으면 어디로 옮겼는지 적는다.

## 9. 발주 전 확인 9줄

1. 계층별 슬롯을 지정했는가 (프레임 n + 적용 n + 종합 1)
2. 미결정 안건을 목록으로 못박았는가
3. 부서·현업 의견을 대안으로 등재하라고 했는가
4. 과업 범위의 경계를 적었는가
5. 문안 언어 계약을 붙였는가
6. 없는 수치를 만들지 말라고 했는가
7. 자기검증표 G1~G9를 요구했는가
8. 한 게이트만 발주했는가
9. 원천 파일을 장 번호별로 대게 했는가
